## 5. Decisions, and things a reader should not over-trust

* **"E4" has no referent in the repository.** The card body asked for `Status` to say "E1a→E3e done,
  E4 out of scope". `SPEC.md` §5 ends at E3 (plus E2.5); the only "E4" in the tree is a note in
  `.gauntlet/e3-fix-serving-backend.qa.md` recommending the serving work as "the E4/`serve` card".
  The README therefore names the **surfaces** that are not in v0.1.0 (HTTP/MCP serving, the optional
  E2-v2 re-measurement) instead of inventing a milestone.
* **`serve`/`mcp` are stubs and must be described as such.** `src/typed_gguf/api/{http,mcp}.py` are
  4-line placeholders and both commands exit 3. The README documents the specified surface, marked
  "not implemented in v0.1.0"; `test_public_docs.py` pins the marker against `cli.main`'s real exit
  codes, so a later release that ships them must update the sentence.
* **The GitHub home does not exist yet.** `pyproject.toml` names
  `https://github.com/Rybens92/typed-gguf` as Homepage; that URL returns 404 today (no remote is
  configured either). The quickstart's `git clone` line is therefore the *publish-step
  dependency*, not a working instruction yet — flagged in the completion metadata.
* **Determinism, precisely.** SPEC A5 promises byte-identical answers for
  (model, backend, `threads=1`) after stripping `timings`; the two `--threads 1` runs above agree on
  every answer and differ only in `engine.fit.budget_bytes`, which is a host reading (free memory)
  refreshed per request. The README says that instead of implying the whole envelope hashes equal.
* **A git worktree of this repo fails the rename's naming gate** (found while running the RED tree):
  `.git` is a *file* in a worktree, and its `gitdir: …/ggufone/.git/worktrees/…` line contains the
  old name, so `tests/test_typed_gguf_surface.py::test_the_living_surface_carries_no_old_name`
  reports a false offender (the walk skips a `.git` **directory**, not the pointer file). Reported
  to the coordinator as a follow-up card; not fixed here (it is the rename card's gate).
* **The host data home moved while this card ran.** `/var/home/rybens/.local/share/typed-gguf`
  appeared at 15:15 (a runtime bundle + `runtime.json` whose `libllama.so` hash is the pinned
  `8d72d777…`), while the pre-rename `…/share/ggufone/` is still on disk — i.e. the operator
  migration from `.t5f9/receipts.md` §8 was performed (copy, not move) during this session. Every
  number in this card comes from the isolated `.t07b5/home`, so nothing here depends on it.
* **`TYPED_GGUF_HOME` pointing inside a path with the old name false-fails the rename gate.** With
  `TYPED_GGUF_HOME=$PWD/.t07b5/home` exported, `cli version` prints the home, and the gate's
  `OLD_NAME not in output` assertion trips on the *checkout directory's own name*
  (`…/workspace/ggufone/…`) — `1 failed, 1360 passed` in the middle of this card, green again with
  the variable unset. Any worker verifying in this checkout should `unset TYPED_GGUF_HOME` (or keep
  the home outside the checkout). Same class as the worktree finding above; both are in the
  follow-up card.
* **`… | tee log` hides the exit code.** The first `doctor` receipt recorded `doctor_exit=0`
  because the pipeline reports `tee`'s status; `doctor` actually exits **2** on this box (warnings:
  the CUDA→Vulkan pre-flight fallback, `model.present` before the pull). The README's exit-code
  sentence is written from the direct runs and from `cli.py` (`ok`→0, `warnings`→2, `failures`→1),
  not from that receipt.
* **The acceptance card's README items (comment 129) are all addressed**: one invocation form
  (`uv run typed-gguf …`, with the `PATH` caveat stated), the quoted `ask` response is this card's
  own run on the README's own state (confidence `0.606`, coverage `0.999`, not the 0.91
  illustration), a `doctor` exit-code sentence in the quickstart, and the two competing quickstart
  blocks collapsed into one. Placement is named next to the timings (`this box, Vulkan, no policy
  flags`).
